1 — the sheet

This must match the PNG you drop in the mod's sprites folder. If you loaded a GIF, use Download PNG below and put that file there.
20 is the game's own scale and almost always what you want. The stock projectile sprites are tiny — the Popper's is 7×7 px (0.35 world units).
The in-game size slider is the friendly end of the same setting: drag right for bigger, left for smaller, and the readout tells you how your largest sprite compares to the Popper. It is non-destructive — it only changes the number written into the .json, never a pixel of your art, so it is the knob to reach for first. (Under the hood it is pixelsPerUnit inverted: more pixels per unit means a smaller sprite, which is backwards for a size slider.) Watch the scale check panel while you drag.

Drawing a muzzle flash? pixelsPerUnit does nothing for it — ignore this dial entirely. A muzzle flash is drawn by a particle system, not a sprite renderer: every stock one is a Billboard particle with no 3D size, which means a square quad whose width comes from the particle's own startSize (1 world unit for the main flash). Your art is mapped onto that quad whatever its pixel size, so this slider cannot make a flash bigger or smaller.
Two things that do matter: draw it square, because a tall or wide picture is stretched onto that square quad; and the stock flash art is 20×20, which is the size worth copying.

Drawing a module card icon? The stock ones are 24×24, and square — that is the size to copy. pixelsPerUnit is ignored for icons: the mod rescales any icon to the stock footprint for you, so this dial only matters if the same art is also used as a projectile. What you do have to get right is the shape, because an icon is drawn in two places that disagree — the card on the grid stretches art to a square, while the pickup lying on the ground keeps its proportions. Draw it square and both look the same. (Icons are also tinted by the module's colour, so draw white or grey unless you set that colour to #ffffff.)

2 — clean up the image

Art exported with a solid backdrop needs that colour turned into transparency, or every shot flies around inside a coloured box. Tolerance widens the match for anti-aliased or slightly dithered edges — start at 8, raise it if a fringe survives, lower it if parts of the sprite vanish. Auto-detect in step 3 also depends on this: with no transparency the whole sheet is one island.
Resamples the whole sheet with nearest-neighbour, so pixel art stays crisp instead of going blurry, and rescales any rects you already cut. Use this when the art is drawn far bigger than the game's — stock projectile sprites are about 7×7 px. The alternative is leaving the image alone and raising pixelsPerUnit in step 1, which shrinks it in game without touching the file; that keeps more detail but costs more memory and can look too fine next to the game's chunky art.
Crop. Auto-trim shaves off every fully transparent edge, so a tall strip with wide empty margins gets tight instantly. To crop to a specific region instead, set what dragging does below to crop and drag the box you want to keep. Either way the sprite rects you have already cut move with the image, and any that fall outside are dropped.
Cropping bakes. The cropped pixels become the new working image, so the background-removal and shrink settings above reset to neutral (they are already applied). Undo restores the file as loaded — and re-loading the PNG always gets you back to square one.

3 — cut out sprites

Finds every island of non-transparent pixels and boxes it, the way Unity's own importer does. gap merge joins islands within that many pixels — raise it to 1–2 if one sprite has detached bits (a dot over an i, sparks round a bullet). The button scans the whole sheet and starts the list over.
Detect in an area. Pick the second option (or just hold Shift while dragging) and the box becomes a search region instead of a sprite: every island inside it is found separately, using the same three settings above. Results are added to the list, so you can work a messy sheet one region at a time — and re-dragging over the same area refreshes it rather than duplicating, since any sprite already wholly inside the box is dropped first. Islands that run past the edge of your box are cropped to it.
For evenly spaced sheets and flipbooks. Leave cols/rows at 0 to fill the whole image automatically.
drag a box to add one by hand, or Shift-drag to auto-detect inside it

4 — sprites

namexywh pivot
x,y is the sprite's top-left corner with y counting downward — the same as every image editor. The mod flips it for Unity. Editing them moves where the sprite is read from; it does not move the art. To rearrange the art itself, repack:
This is how you get a small PNG. It lifts every sprite out and packs them shoulder-to-shoulder into the smallest tidy sheet it can, throwing away all the empty space between them — a 60×1920 strip of 32 mostly-empty frames becomes something like 104×60. The art moves and the rects follow, so your sprites and animations keep working untouched.
Padding leaves a transparent gap between neighbours; 1 is a safe default and stops any chance of a neighbour's edge bleeding in.
Like cropping, this bakes: the packed pixels become the new working image and the settings in step 2 reset. Remember to Download PNG afterwards — the old file on disk is the wrong size now.

5 — animation

Builds one animation from every sprite above, in the order they are listed. Frame order comes from that list and nothing else — the _1 / _2 numbers on auto-named sprites only keep the names unique, they are not frame numbers. Reorder with the arrows.
Naming — read this once and never trip on it again. A sheet contains two kinds of named thing, and the weapon points at one of them by name — never at the .png or the .json filename.
• sprites are still frames, named <sheet>, <sheet>_1, <sheet>_2… (the numbers only keep them unique, they are not frame numbers)
• the animation is the flipbook, named <sheet>Anim
So for a sheet called petrolbm.png, "projectileSprite": "petrolbm" is one frozen frame while "projectileSprite": "petrolbmAnim" is the animation. Rename either freely — the export panel below always shows the exact line to paste, and it prefers the animation when you have one.

6 — scale check

Every sprite drawn at its real in-game size, next to three stock things. Only the first is a target to hit:
• Popper bullet — 7×7 at 20 ppu. If a bullet of yours dwarfs it, raise pixelsPerUnit or draw smaller.
• Module icon — 24×24 at 40 ppu. No matching needed: the mod rescales an icon to this whatever you drew. It is here to show how big an icon really is on the ground.
• Muzzle flash — 1 unit square, and this swatch never moves when you drag the size slider, because a flash is a particle: its size comes from the particle system's own startSize and pixelsPerUnit is not involved at all. Your art is stretched onto that square quad, so the only thing to get right is drawing it square.

7 — export

(load an image and cut a sprite)
Put the .json and the PNG in BepInEx\plugins\...\sprites\, then paste this into your weapon's JSON. Copy the name exactly — it is the name of a sprite or animation inside the sheet, not the filename: 
"weapon": { "projectileSprite": "..." }
The same name works in three other places — one sheet can serve all of them:
"weapon": { "muzzleSprite": "<name>" } — the muzzle flash. An ...Anim name is usually what you want, and add "muzzleSpriteFps" because a flash only lives about 0.4 seconds: frames ÷ 0.4 is the fps that plays it through exactly once (6 frames → 15, 20 frames → 50). Too slow and you only ever see the first frame or two.
"module": { "icon": "<name>" } — the module card icon, in this mod or in Module Forge.
"weapon": { "trail": { "sprite": "<name>" } } — the trail puffs.
